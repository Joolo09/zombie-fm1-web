# Zombie Lab 0.1.0 — отдельная тестовая прошивка FM-1

Основная Zombie Core 0.7.1 не редактируется и не пересобирается. Lab имеет отдельные
исходники, отдельную копию аппаратной основы, имя USB `Zombie Lab FM-1`, протокол
`ZLAB/1/0.1.0` и идентификатор пакета `FM-1_62000100`. SHA-256 исходников и готовых
файлов основной версии зафиксированы в MAIN-BASELINE.json и проверяются сборщиком.

**Установка Lab временно заменяет приложение на самом FM-1.** Одновременно держать
и запускать две прошивки этот пакет не умеет. Сам сборщик ничего в устройство не
устанавливает. Сборка и симулятор проверены; физический FM-1 не проверен.

## Что исследуется

- Реальный JEDEC ID из штатного чтения при старте. Предполагаемая ёмкость выводится
  по коду JEDEC; это не проверка адресации всей микросхемы.
- CRC32 и признак «все FF» для каждого из 73 секторов известной области
  0x97000–0xDFFFF. Чтение разбито на небольшие порции. Пустой сектор не означает,
  что он свободен по разметке. Само содержимое и звуки в JSON не включаются.
- Запись и проверка шаблона в собственном выделенном RAM-буфере 32 КиБ. Это
  проверяет буфер, а не измеряет весь физический объём RAM и не ищет неизвестную RAM.
- USB в штатной роли устройства: конфигурация, счётчики пакетов/ошибок и MIDI SysEx ping.

**USB-host, диск/флешка, FAT, питание 5 В с USB-C, дополнительные RAM/flash и
перенастройка SDRAM не включены и не проверяются.** CPU1, радио и USB audio выключены.
Эта версия нужна для первого отчёта перед дальнейшими экспериментами с USB-host.
Пакет рассчитан на штатный FM-1 с родной flash; после аппаратной замены чипа
совместимость загрузки/обновления не гарантируется.

## Установка и отчёт

1. Сохрани нужные проекты и исходные WAV из своей текущей прошивки.
2. Закрой DAW и другие MIDI-редакторы. Запусти Zombie-Lab-0.1.0.exe.
3. Подключи FM-1 кабелем данных; выбери устройство и установи встроенный пакет Lab.
   Это обычное обновление с явным запуском установки, не автоматическая операция.
4. После перезагрузки открой «Диагностика / отчёт» из этой же программы. В Chrome
   или Edge нажми «Подключить Zombie Lab», разреши MIDI SysEx и выбери её порты.
5. Запусти чтение карты flash и RAM-тест, дождись завершения. Проверь SysEx ping,
   затем скачай JSON-отчёт. Сканирование занимает около 20 секунд.

На устройстве: HOME — обзор; EDIT — flash; ENV — RAM; GLO — USB; SELECT — страницы.
PLAY начинает чтение flash, REC — RAM-тест. SAVE ничего не сохраняет. Экран Lab
на английском, веб-диагностика на русском. В симуляторе явно показано SIMULATED,
JEDEC не подменяется выдуманным значением.

## Запрет записи и возврат

Диагностический протокол содержит только идентификацию, чтение, ping и запуск
этих двух тестов. Операции сохранения и записи в область данных отключены в
изолированной аппаратной основе. Драйвер flash разрешает erase/program только
служебному диапазону OTA 0xE0000–0xE4FFF для штатного обновления/возврата.
Это не обещание «вообще ни одного изменения flash»: установка и OTA-путь пишут
прошивку и служебные данные. Диагностика не сохраняет проекты, PCM, SYS,
раскладку пэдов, калибровку или Bluetooth. Калибровку в Lab проводить не требуется.

Для возврата к нашей основной версии в этой же программе нажми «Открыть .fwsc…»,
выбери `rollback/Return-to-Zombie-Core-0.7.1.fwsc` и выполни обычную установку.
Это точная копия сохранённой основной прошивки, SHA-256 совпадает. Либо воспользуйся
своим прежним установщиком Zombie Core 0.7.1. Штатные данные основной версии при
нормальном обновлении остаются на прежних адресах.

Если до Lab у тебя заводская или другая прошивка, для возврата нужен её пакет:
папка rollback содержит именно Zombie Core 0.7.1, а не заводскую M-VAVE.

## Сборка

`python -X utf8 zombie-lab/build.py` — отдельные .fwsc, EXE и ZIP, используя уже
подготовленные инструменты проекта. `--firmware-only` — только прошивка и сайт;
`--installer-only` — собрать EXE для уже готовой Lab; `--package-only` — перепаковать.
Все результаты — в zombie-lab/output. Основной tools/build-core.py не вызывается.
Для сборки потребуются те же .tooling/SDK/runtime, что были настроены для проекта.

Оригинальный код приложения, протокола, тестов и страницы — MIT. Изолированная
аппаратная основа fm1-base/felucca-bsp — MPL-2.0, изменения находятся только в Lab:
захват boot JEDEC и запрет сохранений/записей данных. Генерируемые словари reader
не опубликованы; их example.invalid URL не нужен для веб-диагностики.
