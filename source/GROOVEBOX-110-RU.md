# Zombie Groovebox 0.11.0 beta

Пять синтезаторных дорожек и своя драмка в шестой. Сэмплер и Lab не менялись.

## Что изменилось

- Новый проект пустой. PLAY не запускает заводские ноты и барабаны.
- Удалён старый второй источник драм-паттерна. Старые GM-ноты переносятся один раз; очищенная драмка не восстанавливается из скрытой копии. Осиротевшее сохранение кита не накладывается на новый проект или проект сэмплера.
- На HOME — оригинальный блочный зомби: дыхание и моргание в покое, движение при PLAY, красные глаза при REC. Видны заполненные дорожки, число нот/ударов, значения четырёх ручек и подсказки.
- Ручки ENV/EDIT/SEL на шестой дорожке управляют её звуком, длиной, уровнем, строем, панорамой, вероятностью и эффектами. ARP на драмке открывает её секвенсор.
- В браузере работает полный код C: экран, кнопки, запись, звук и сохранение. Быстрые нажатия проходят отдельными событиями; сочетания не оставляют вторую кнопку зажатой.

## Управление

SELECT — темп; ALGO — дорожка; PRESET — страница/банк. Подписи K1–K4 показывает экран.

1. REC без PLAY: пошаговая запись. Сыграть ноту/аккорд, отпустить — следующий шаг.
2. PLAY, затем REC: запись во время воспроизведения.
3. SEQ: редактирование; SEQ + EDIT: удалить шаг.
4. SEQ + REC: очистить партию (в драмке — выбранный звук).
5. SEQ + последняя чёрная клавиша: очистить всю выбранную дорожку, включая все звуки драмки.
6. EDIT + OCT−: отмена; EDIT + OCT+: повтор.
7. HOME удерживать, дважды нажать 15-ю белую клавишу за три секунды: новый пустой проект. SAVE сохраняет его вместо старого. До SAVE перезапуск возвращает сохранённый проект.

В эмуляторе включить «Удерживать кнопки для сочетаний», нажать SEQ, нужную вторую кнопку, затем SEQ ещё раз. PLAY/REC/SAVE остаются обычными нажатиями. SAVE хранит проект только в этом браузере, отдельно от FM-1.

## Проверки и ограничения

Повторяемая проверка: `python -X utf8 tests/run_groovebox_audit.py --build` с настроенными JIELI_TOOLCHAIN, AC79_SDK, CC и ZIG. Сборка эмулятора: `python source/build-emulator.py` после сборки прошивки. Для локального запуска страницы нужен HTTP-сервер.

Результаты и контрольные суммы: [emulator/audit.json](../emulator/audit.json), [emulator/build.json](../emulator/build.json).

Проверены: все 14 кнопок, семь энкодеров, 27 клавиш; страницы и удержания на шести дорожках; запись/редактирование/удаление/отмена; сохранение и перезапуск; перенос старых проектов; синтезаторы и драмка; MIDI clock, solo/mute, arp, FX и DAW-режимы. Отдельно проверен настоящий код журнала flash на моделируемой NOR-памяти с обрывами записи и повреждением CRC. Синтез пяти дорожек сравнивается с предыдущей версией. Нагрузочная последовательность включает 350 смешанных действий.

Это программные проверки. Реальная скорость процессора FM-1, сенсорная чувствительность, физический USB/загрузчик и отключение питания на устройстве ими не подтверждены. «Все ошибки устранены» этот отчёт не утверждает.

## Идеи из других прошивок

[Firmware Hub](https://thefirmwarehub.com/) используется как каталог. Изучены описания управления [Orbit](https://github.com/dspaudio/orbit) и [Sloop](https://github.com/dspaudio/orbit/blob/main/README-SLOOP.md): явная загрузка демо, подтверждение очистки, предсказуемые удержания и общий транспорт. Здесь применены пустой запуск, подтверждение нового проекта и подсказки. Целиком чужой движок или интерфейс не переносился. Полный аудит всех проектов каталога не проводился; новые музыкальные функции стоит добавлять после проверки основы на FM-1.
